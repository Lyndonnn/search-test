## 1. Project Goal

Project name: **DAG-IG: Dependency-Aware Information Gain for Multimodal Search Agents**

Core idea:

- Standard IG-Search gives credit to an observation only if it directly improves final answer likelihood.
- DAG-IG additionally gives credit to an early observation if it enables a later useful action, especially `crop/image clue -> search query -> evidence -> answer`.
- The current most promising setting is **Pix2Fact-style delayed-credit search**, not generic FVQA.

Current working claim:

> DAG-IG shaping should improve evidence-directed search action quality compared with outcome-only and local-IG supervision, especially when the local visual clue does not directly answer the final question but enables the correct search query.

- `dagig`: local clue and search query receive future-action IG credit; answer remains supervised.

## 7. Current Scientific Status

What is established:

- The code path works end-to-end.
- Pix2Fact data has delayed-credit structure.
- DAG-IG shaping has a positive pilot signal on evidence-only query retrieval.
- The right metric should be evidence retrieval utility, not only query string F1.

What is not established:

- No paper-level result yet.
- Current dataset is too small.
- Dev set has only 6 examples.
- Retrieval corpus is too small.
- 7B has not been run on this data yet.
- Real web search / SerpAPI has not been integrated into this Pix2Fact pilot.

Current recommendation:

> Do not tune more on the 30-sample package. It has served its purpose. The next bottleneck is data scale and harder retrieval distractors.

```text

search_query ignores local_observation
many near-duplicate companies/entities
same company/domain appears in both train and dev
```

Split rule:

- Do not random split by row.
- Group by normalized entity/company/domain/email domain.
- Keep the same group out of both train and dev.

## 9. Harder Retrieval Corpus Requirement

The v1 retrieval corpus of 30 items is too easy.

For v2, build `evidence_corpus.jsonl` with at least:

```text
1 positive evidence per sample
4-10 hard negatives per sample
random negatives from other samples
same-domain or same-question-type negatives
similar-entity negatives
```

Target retrieval candidate size:

```text
>= 200 docs for v2
>= 500 docs preferred
```

Evidence doc schema:

```json
{
  "doc_id": "...",
  "sample_id": "...",
  "text": "...",
  "is_positive": true,
  "entity": "...",
  "domain": "...",
  "source": "selected|hard_negative|random_negative"
}
```

Main metrics for v2:

```text
evidence_only retrieval_top1
evidence_only retrieval_top3
evidence_only retrieval_mrr
target_score_margin_mean
local_observation F1
answer_from_evidence F1
```

